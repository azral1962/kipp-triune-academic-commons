01 / Latar belakang

Mengapa proyek ini ada?

Kuliah KIPP memandang komunikasi bukan hanya transfer pesan. Tujuannya membangun pemahaman, kepercayaan, ketertarikan, tanggung jawab, dan tindakan. Proyek ini menyediakan medan nyata untuk mempraktikkan semua kompetensi tersebut dalam pekerjaan akademik.

MASALAH

Pengetahuan tercerai-berai

Catatan, contoh kode, dan pengalaman belajar sering tersimpan sendiri-sendiri serta hilang saat semester berakhir.

PELUANG

Kolaborasi + AI

Mahasiswa mampu saling mengajar, mengkritisi gagasan, dan menggunakan AI untuk memperluas kegiatan intelektual secara bertanggung jawab.

SOLUSI

Academic Commons

Satu portal yang menghubungkan knowledge, skills, prompt, learning path, diskusi, kode, dan problem solving.

Lima domain komunikasi KIPP

01. Diri sendiriKesadaran dan refleksi; mengelola proses belajar pribadi.
02. SahabatMendengar aktif, empati, saling mengajar dan memberi umpan balik.
03. ProfesionalKoordinasi tim, komunikasi kebutuhan pengguna, penciptaan nilai.
04. KomunitasMusyawarah, peer review, forum, dan kecerdasan kolektif.
05. PublikPublikasi pengetahuan, storytelling, manfaat bagi pembelajar lain.
02 / Kerangka intelektual

Triune Intelligence

KIPP memberdayakan tiga sumber kecerdasan yang saling memperkaya, bukan saling menggantikan.

◉

Individual Intelligence

◎

Collective Intelligence

04 / Strategi komunikasi

TAIDA menggerakkan dari pemahaman menuju tindakan

TAIDA digunakan baik untuk mengajak pengguna belajar maupun untuk menggerakkan tim berkolaborasi.

T — Target

Siapa pengguna? Apa perubahan dan ukuran keberhasilannya?

A — Attention

Bagaimana menunjukkan masalah akademik yang penting?

I — Interest

Bagaimana pengguna merasakan relevansi solusi?

D — Desire

Bagaimana nilai dan manfaat menumbuhkan motivasi?

A — Action

Apa yang dicoba, dipelajari, direvisi, dan dibuktikan?

Contoh: mahasiswa kesulitan membaca paper → mengenali kebutuhannya → melihat tutorial relevan → ingin mencoba prompt pembaca kritis → mengerjakan matriks literatur dan menguji kebenaran sitasi. Sasaran akhirnya adalah kompetensi pengguna, bukan jumlah prompt.
05 / Kesepakatan bersama

Project Charter

Dokumen dasar untuk dimusyawarahkan, bukan peraturan yang otomatis sudah disahkan.

Visi

Membangun komunitas pembelajar yang mengembangkan kecerdasan individu, kolektif dan AI untuk menciptakan nilai akademik bersama.

Kompetensi komunikasi, kemampuan akademik, penggunaan AI yang kritis, dan hasil yang dapat digunakan ulang.

11 / Panduan mahasiswa

Workflow Git & GitHub

Gunakan repositori kelas sebagai tempat berkarya. Git menyimpan sejarah perubahan; GitHub mendukung koordinasi, review, dan penerbitan bersama. Pelajari tiga jalur: browser, GitHub Desktop, atau terminal.

1

Pilih artefak dan baca charter

Temukan ID artefak di katalog dan koordinasikan tugas dengan tim. Jangan mengubah ID yang sudah disediakan.

2

Buat atau ambil GitHub Issue

Issue memuat tujuan, sasaran pengguna, pekerjaan, pemilik, dan target selesai. Hindari Issue ganda.

3

Buat branch terpisah

Gunakan contoh nama tim-03/K-R01-baca-paper. Jangan langsung mengedit branch utama main.

4

Isi, jalankan, dan periksa artefak

Tulis di file .qmd yang tersedia, masukkan referensi, visual/latihan, bukti pengujian, serta keterangan AI.

5

Commit & push

Simpan perubahan dengan pesan bermakna dan kirim branch ke GitHub. Pastikan tidak ada API key, data sensitif, atau file tak relevan.

6

Buka Pull Request (PR)

Ajukan perubahan untuk ditinjau tim lain, jelaskan ringkasan, hasil uji, dan pertanyaan yang masih terbuka.

7

Peer review, revisi, lalu merge

Reviewer memberi komentar konkret. Penulis memperbaiki pada branch yang sama. Koordinator menggabungkan PR bila quality gate terpenuhi.

8

Publikasi dan refleksi

Publikasikan artefak yang layak, catat pembelajaran individual, umpan balik, dan nilai yang tercipta.

JALUR A

GitHub Web

Browser saja: edit berkas, commit ke branch baru, buka PR. Cocok untuk penulis materi pemula.

JALUR B

GitHub Desktop

Antarmuka visual untuk clone, branch, commit, push, dan PR. Cocok untuk kontribusi lokal tanpa perintah.

JALUR C

Git Terminal

Kontrol penuh untuk kode, notebook, validasi otomatis, dan pemecahan konflik perubahan.

Contoh perintah Git

# Ganti ORGANISASI dengan alamat resmi kelas
 git clone https://github.com/ORGANISASI/kipp-triune-academic-commons.git
 cd kipp-triune-academic-commons
 git switch main
 git pull --ff-only origin main
 git switch -c tim-03/K-R01-baca-paper
 # Sunting file artefak sesuai tanggung jawab
 python scripts/check_artifacts.py
 git status
 git add topics/02-literature-research/01-knowledge/02-01-01-k-r01.qmd
 git commit -m "docs(K-R01): tambah panduan pembacaan kritis"
 git push -u origin tim-03/K-R01-baca-paper

Alamat GitHub resmi belum ditetapkan. ORGANISASI adalah placeholder. Jangan menggunakan alamat contoh sebagai tautan repositori aktif.

12 / Penjaminan mutu

Peer review dan quality gate

Kontribusi yang banyak tidak otomatis berarti karya yang berkualitas. Artefak perlu diperiksa oleh tim lain sebelum diterbitkan.

Checklist sebelum publikasi

0 / 9 selesai

  • Identitas penulis, tujuan, dan pengguna jelas.
  • Klaim dan referensi dapat diverifikasi pada sumber asli.
  • Contoh, prompt, kode atau demonstrasi sudah diuji.
  • Penggunaan AI dan keterbatasannya dinyatakan transparan.
  • Tidak ada data sensitif, kredensial atau karya tanpa izin.
  • Ada komentar reviewer independen dan revisi yang ditindaklanjuti.
  • Petunjuk penggunaan, latihan, dan cara asesmen tersedia.
  • Artefak dicoba oleh pengguna bukan pembuatnya.
  • Status dicatat jujur: draf atau sudah ditinjau.
Label reviewed berarti lulus proses review internal proyek, bukan sertifikasi kebenaran ilmiah formal. Konten pada starter repository semuanya masih draf.

14 / Etika dan keberlanjutan

Manusia bertanggung jawab; AI mendukung

Ketepatan ilmiah

Periksa klaim, sitasi, data, dan keluaran AI. Jangan mengarang referensi atau menganggap teks yang meyakinkan pasti benar.

Privasi dan lisensi

Hindari mengunggah data pribadi, rekaman tanpa izin, API key, atau materi yang hak penggunaannya tidak jelas.

Relasi dan tanggung jawab

Gunakan AI sebagai tutor, cermin, penerjemah, atau kopilot terbatas; keputusan akademik dan komunikasi sensitif tetap di tangan manusia.

Keberlanjutan setelah 21 hari

Versi 0.1 menjadi fondasi proyek berikutnya. Angkatan selanjutnya memperbarui modul, menguji ulang prompt, memperbaiki kode, dan memperluas forum. Artefak yang tidak terawat perlu diberi penanda versi dan status.

Fitur masa depan P3: tutor adaptif, asisten penelaah literatur berbasis RAG, penguji argumen, lab notebook interaktif, visualisasi berbasis data, dan simulator keputusan. Tidak menjadi syarat pilot.

Landasan dari sumber kuliah

Kerangka komunikasi, lima domain, TAIDA, serta pembelajaran manusia–AI merujuk pada materi Komunikasi Interpersonal dan Publik (2026) dan kuliah.pdf. Elaborasi Triune Academic Commons, pengelompokan 12 tim, target 42 artefak, serta rancangan tiga minggu merupakan proposal kolaboratif dari percakapan perancangan proyek ini. Sumber kuliah tidak dengan sendirinya menetapkan charter atau bobot proyek tersebut.

Apakah website ini sudah merupakan portal produksi yang terhubung GitHub?

Belum. Ini website informasi proyek yang dapat dijalankan lokal dan dipublikasikan sebagai situs statis. Katalog menggunakan snapshot CSV starter repository. Perubahan langsung di GitHub baru akan tercermin setelah berkas data website diperbarui atau dibuat otomasi sinkronisasi.

Apakah mahasiswa harus menguasai pemrograman?

Tidak. Untuk membuat materi dan memberikan review, mahasiswa dapat menggunakan GitHub melalui browser. Pemrograman menjadi penting terutama pada tema kode dan analisis data.

Bagaimana jika target artefak terlalu tinggi?

Project Coordination Board dapat menyesuaikan ruang lingkup dengan mencatat alasan dan dampak. P0 dan P1 berkualitas lebih penting daripada mengejar P2 tanpa validasi.

Bisakah dokumen dipakai angkatan berikutnya?

Bisa, setelah hak, lisensi, dan penanggung jawab pemeliharaan disepakati. Perubahan berikutnya tetap perlu review dan dokumentasi.
